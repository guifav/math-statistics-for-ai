# Politica de Seguranca

Este e um repositorio educacional, mas ainda pode receber problemas de
seguranca, como exposicao acidental de credenciais, exemplos inseguros ou
dependencias vulneraveis.

## Como reportar

Nao abra uma issue publica para vulnerabilidades sensiveis.

Use o recurso "Report a vulnerability" do GitHub, quando disponivel, ou entre
em contato diretamente com o mantenedor do repositorio.

Inclua no relato:

- Arquivo ou notebook afetado.
- Descricao objetiva do risco.
- Passos para reproduzir, quando aplicavel.
- Impacto esperado.
- Sugestao de correcao, se houver.

## Escopo

Sao considerados dentro do escopo:

- Credenciais, tokens ou caminhos privados versionados por engano.
- Exemplos que ensinem praticas inseguras sem aviso didatico.
- Dependencias com vulnerabilidades relevantes para execucao local.
- Notebooks que executem comandos inesperados ou destrutivos.

Ficam fora do escopo:

- Relatos sem impacto pratico demonstravel.
- Vulnerabilidades em servicos externos nao controlados por este repositorio.
- Alertas automatizados sem contexto ou caminho de exploracao.

## Expectativa de resposta

O mantenedor tentara confirmar o recebimento, avaliar o risco e planejar a
correcao conforme disponibilidade. Correcoes aceitas devem passar pelo mesmo
processo de pull request e validacao do projeto.
